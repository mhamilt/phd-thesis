To effectively tackle the problem of digital musical instrument conservation, we require frameworks that address each of the components discussed above.

Entangled within the concept of digital preservation is the movement toward Open Science \cite{unesco_open_2021}, a philosophy of academic research that advocates for openly sharing not only the results of research\footnote{``e.g., original scientific research results, research data, software, source code, source materials, workflows and protocols, digital representations of pictorial and graphical materials, and scholarly multimedia material'' \cite{unesco_open_2021}} but also the processes and methodologies necessary to achieve those results. Digital technologies make concepts like Open Science feasible, but when applied to digital assets, a robust framework is required to make Open Science achievable. The FAIR principles provide such a framework, focusing on the ``Findability, Accessibility, Interoperability, and Reuse [FAIR] of digital assets'' \cite{wilkinson_fair_2016}:

\begin{itemize}
    \item \textbf{Findability}: Digital assets are described with rich metadata and assigned a persistent location.
    \item \textbf{Accessibility}: The protocols used are open, free, and universally implementable.
    \item \textbf{Interoperability}: Data or tools from independent sources can integrate or work together with minimal effort.
    \item \textbf{Reuse}: Digital assets are released with a clear and accessible data usage license.
\end{itemize}

Version control systems such as git provide a straightforward way to track and tag versions of software, while platforms like GitHub enable broad distribution and public access.

This thesis aims to demonstrate the considerations necessary to adhere to these four FAIR principles, particularly within a cross-disciplinary project. All digital assets—whether source code, measurement data, or CAD files—are managed accordingly.

For software to be FAIR, it must also be citable \cite{soito_citations_2016}, a process that has historically lacked standardization. Making software citable involves adhering to guidelines not only for research software authors \cite{smith_software_2016} but also for those citing the software \cite{katz_recognizing_2021} and for journals cross-referencing such citations \cite{stall_journal_2023}.

All digital outputs of this thesis have been version-controlled using git. Repositories are hosted on GitHub to allow for public access. A \textit{release} is defined as any self-contained working version of an asset used during research. Digital assets are dynamic and can undergo changes; a release represents a snapshot—a final form at a particular moment in time.

To enable persistent referencing, digital object identifiers (DOIs) are assigned to software releases \cite{smith_software_2016}. Although open software is inherently evolving, which complicates cite-ability and reuse, public, online, version-controlled repositories like GitHub help software comply with FAIR principles. However, longevity remains a concern \cite{smith_software_2016}. To address this, software releases are archived on the Zenodo platform, which assigns DOIs to ensure persistent access \cite{smith_software_2016, stall_journal_2023}.

This persistence of location addresses one aspect of longevity; another critical aspect is reusability. Open Science and FAIR focus on digital research outputs, but additional work is required during the authoring process to ensure reproducibility \cite{perkel_challenge_2020}. Software should be expected to run and rerun in the future, yet this is hindered by rapidly evolving technology and insufficient documentation \cite{robert_reproducibility_2020}.

While this discussion has focused on digital software, digitally designed physical hardware presents additional challenges. Such hardware involves not only software but also firmware that operates the electronics. In the field of digital musical instrument (DMI) design, long-term reusability remains a persistent challenge \cite{fiordelmondo_towards_2025}. Electronic hardware design typically includes Computer Aided Design (CAD) and Computer Aided Manufacture (CAM) steps, requiring the preservation of schematics and bills of materials \cite{calegario_documentation_2021}. CAD tools can pose preservation risks; for example, during this thesis, Autodesk announced the discontinuation of the popular Electronic Design Automation software EAGLE by July 2026 \cite{autodesk_eagle_2024}. Nevertheless, a conscious decision was made to continue using the EAGLE format for PCB design. Similar to how the discontinuation of Python 2 has archival benefits as an ``advanced programming language that is guaranteed not to evolve anymore'' \cite{rougier_loupe_2020}, the discontinuation of EAGLE effectively freezes its XML file standard. Furthermore, EAGLE files remain usable with other EDA software such as the open-source KiCAD \cite{kicad_eagle_2024}.

\textcite{perkel_challenge_2020} provides a checklist—aggregated from the ReScience C initiative and its challenge—to encourage researchers to replicate results from software older than 10 years. Key recommendations include version control and archiving. In line with this guidance and the broader literature \cite{smith_software_2016, stall_journal_2023}, git version control repositories have been used to track changes and tag distinct versions. All repositories have been archived on the Zenodo platform, where each repository is assigned a base DOI and each tagged version receives its own DOI.

All digital assets are licensed under the GPLv3 license, following recommendations to provide as open permissions as possible \cite{stall_journal_2023}. The GPLv3 license allows copying, distribution, and modification of source files, with the stipulation that any modifications are also made available under the same license \cite{gplv3}. Source code repositories for this thesis conform to the current Software Sustainability Institute guidelines and have undergone assessment by the Software Sustainability Institute at the University of Edinburgh \cite{ssi_online_2025}.
